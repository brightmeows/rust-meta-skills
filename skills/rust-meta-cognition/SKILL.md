# Rust 元认知路由

遇到 Rust 编译错误或设计权衡时，不给出表面修复（“直接 `.clone()` 就行”一类），
而是把问题放进三层认知模型定位根源，再给方案。本文件自包含，无子技能文件。

## 核心约束：结论必须有出处

每个层次给出的结论都要有权威出处，不允许凭印象断言：

- **语言事实**（语义、规则、错误码）：The Rust Reference、`rustc --explain E0xxx`、std 文档
- **设计事实**（crate API、惯用法）：crate 官方文档（docs.rs）、crate 的 CHANGELOG
- **领域约束**（业务规则、SLA）：向用户确认，不替用户假设

查得到的现查，引用时注明出处；查不到的如实说明不确定性。这条约束替代一切“先读文件再回答”的流程要求。

## 三层模型

| 层 | 问题 | 范围 | 典型入口信号 |
|----|------|------|--------------|
| L1 语言机制 | 怎么做（HOW） | 所有权、借用、生命周期、trait、并发、错误处理、unsafe | E0xxx、编译错误、panic |
| L2 设计选择 | 做什么（WHAT） | 领域建模、API 设计、架构模式、性能权衡 | “怎么设计”“最佳实践”“该用哪个 crate” |
| L3 领域约束 | 为什么（WHY） | 业务规则、合规、SLA、部署环境 | “构建一个交易系统”“必须可审计” |

三层不是并列的三个话题，而是一条因果链：领域约束决定设计选择，设计选择触发语言机制。

## 入口识别与追溯方向

按问题的入口信号确定从哪层开始、往哪个方向追溯：

| 入口信号 | 入口层 | 方向 | 追溯要问的问题 |
|----------|--------|------|----------------|
| E0xxx、编译错误、panic | L1 | 向上 ↑ | 什么设计决策导致了这个约束？ |
| “怎么设计”“什么模式” | L2 | 先查 L3，再向下 ↓ | 哪些领域约束决定方案形态？ |
| “构建 [领域] 系统” | L3 | 向下 ↓ | 约束之下该选什么模式？ |
| “最佳实践”、权衡分析 | L2 | 双向 ↕ | 两侧的约束与代价各是什么？ |

方向定错是本技能的主要失效模式：从 E0382 直接跳到 `.clone()` 是停在 L1 的表面回答；
“设计支付系统”直接跳到 `rust_decimal` 是跳过 L3 的无据回答。

## 错误码路由

错误码按类别归组，每类别对应一个必须追问的核心问题：

| 类别 | 错误码 | 核心追问 |
|------|--------|----------|
| 所有权 | E0382 E0506 E0507 E0515 E0597 E0716 E0106 | 这份数据应该谁拥有？所有权结构为什么是这样？ |
| 可变性 | E0596 E0499 E0502 | 为什么这里必须可变？共享可变是不是设计问题的信号？ |
| 泛型与 trait | E0277 E0308 E0599 E0038 | 约束来自哪个设计决定？该满足约束还是改设计？ |
| 生态 | E0433 | 依赖与模块结构是否合理？ |

遇到表中没有的错误码：`rustc --explain <code>` 是第一出处，归入最接近的类别后照常追问。

## 追溯流程

1. **识别入口层**：按入口信号与错误码路由定层、定方向。
2. **逐层追溯**：沿方向穿过相关层级，每层收集约束或结论。
3. **逐层取证**：按“核心约束”一节为每层结论找权威出处。
4. **综合输出**：按响应规范给出方案，说明每个选择受哪层约束影响。

## 响应规范

非比较类问题按以下结构回答：

```
## 认知追溯
入口层与路由依据；各层结论及其出处。

### 追溯链
按方向逐层说明：L3 约束 → L2 选择 → L1 实现（或反向）。

### 方案
修复或设计建议，标注每个决定受哪层约束影响；有不确定处如实标注。
```

回答前自检：

- [ ] 每层结论都有出处（文档、编译器输出或用户确认）
- [ ] 追溯方向与入口信号一致
- [ ] 方案说明了层间因果，而非孤立的技术点
- [ ] 不确定处已显式标注，未冒充确定结论

## 比较类问题

“X 还是 Y”“最佳实践是什么”一类问题，先钉判据再比较：比较维度从 L2/L3 推导
（性能预算、团队约定、部署环境），判据不明的先向用户确认。输出取舍表，
每格标注出处；没有明确赢家的组合如实说“取决于判据”。

## 项目默认设置

创建 Rust 项目或 `Cargo.toml` 时使用：

```toml
[package]
edition = "2024"       # 最新稳定版，不用 2021 或更早
rust-version = "1.96"  # 明确 MSRV

[lints.rust]
unsafe_code = "warn"

[lints.clippy]
all = "warn"
pedantic = "warn"
```

## 代码风格硬约定

- 命名：`snake_case`（函数/变量）、`PascalCase`（类型）、`SCREAMING_SNAKE_CASE`（常量）；不用 `get_` 前缀；转换命名 `as_`（廉价借用）/ `to_`（昂贵）/ `into_`（转移所有权）
- 库代码用 `?`，避免 `unwrap()`；确需 panic 语义用带消息的 `expect`
- 每个 `unsafe` 块必须有 `// SAFETY:` 注释说明安全前提
- lint 豁免用 `#[expect]` 替代 `#[allow]`（lint 不再触发时编译器会提醒清理），并附一句原因
- import 排序交给 rustfmt（`group_imports` 与 `imports_granularity` 尚未稳定，需 nightly）：std → 外部 crate → workspace → `super::` → `crate::`

完整权威参考：[Rust Style Guide](https://doc.rust-lang.org/style-guide/)、[Rust API Guidelines](https://rust-lang.github.io/api-guidelines/)。
